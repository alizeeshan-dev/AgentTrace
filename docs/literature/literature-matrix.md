# AgentTrace Focused Literature Matrix

## Review scope

This is a focused background review, not a systematic literature review. Sources were selected for direct relevance to AgentTrace's experimental variables: repository interaction, software-maintenance agents, trajectory observability, deterministic verification, and test-overfitting risk. The matrix was checked against original papers, proceedings pages, or the official specification on 2026-08-20.

Results in the **Main result** column are the source authors' reported results, not independently reproduced findings. The **Relevance to AgentTrace** column is an AgentTrace design inference. A standards document has no experimental result and is labelled accordingly.

| Just, Jalali, and Ernst (2014), [“Defects4J: A Database of Existing Faults to Enable Controlled Testing Studies for Java Programs”](https://homes.cs.washington.edu/~mernst/pubs/bug-database-issta2014-abstract.html), ISSTA 2014. | How can studies use reproducible real faults rather than incomparable seeded faults? | Version-controlled buggy/fixed program pairs with exposing test suites and a common experimental interface. | Initially 357 real bugs from five Java projects. | Dataset size, reproducibility, and test exposure of faults. | The work released a reproducible real-fault database and framework with buggy/fixed versions and corresponding tests. | Motivates immutable base revisions, baseline/fixed behavior checks, and task-level reproducibility. | It is Java-specific, and even comprehensive project tests remain incomplete behavioral specifications. |
| Xiong, Liu, Zeng, Zhang, and Huang (2018), [“Identifying Patch Correctness in Test-Based Program Repair”](https://arxiv.org/abs/1706.09120), ICSE 2018. | Can execution-behavior similarity and generated tests filter test-adequate but incorrect patches? | PATCH-SIM/TEST-SIM compare execution behavior and augment tests to classify patches. | 139 patches from jGenProg, Nopol, jKali, ACS, and HDRepair. | Incorrect patches filtered and correct patches incorrectly blocked. | The approach filtered 56.3% of incorrect patches in the evaluated set without blocking a correct patch. | Demonstrates that a green original suite is insufficient and supports held-out tests plus separate regression measurement. | The method is heuristic, uses Java APR patch sets and dynamic traces, and does not prove correctness for behavior outside its generated tests. |
| Yu, Martinez, Danglot, Durieux, and Monperrus (2019), [“Alleviating Patch Overfitting with Automatic Test Generation: A Study of Feasibility and Effectiveness for the Nopol Repair System”](https://arxiv.org/abs/1810.10614), *Empirical Software Engineering* 24. | Can generated tests reduce incomplete fixes and regression-introducing overfitting in test-suite-based repair? | UnsatGuided incrementally augments Nopol's repair constraints with generated tests. | 224 Defects4J bugs, with detailed repair analysis for bugs Nopol could initially patch. | Incomplete-fix behavior, regression-introduction behavior, and changed/correct patches. | The authors report that generated tests alleviated regression introduction in 16 of 19 affected cases but had minimal positive impact on incomplete fixing. | Directly motivates separating hidden task resolution from regression outcomes and avoiding claims that more tests eliminate overfitting. | The result is specific to synthesis-based Nopol, Java, and generated-test oracles; it does not establish that one feedback loop generalizes to LLM patches. |

## Synthesis for AgentTrace

The literature supports five conservative choices for the AgentTrace experiment:

1. Treat a fixed repository revision, issue statement, task-specific fail-to-pass tests, and baseline pass-to-pass tests as the unit of a reproducible task.
2. Measure repository tool access separately from verification feedback; agent interfaces can materially affect performance.
3. Preserve complete ordered trajectories for diagnosis, but keep deterministic final behavior—not trace appearance—as the correctness criterion.
4. Keep final hidden evaluation inaccessible to the agent so repair cannot train directly on the scoring oracle.
5. Report incomplete fixes and regressions separately because passing an available test suite is evidence, not proof of semantic correctness.

No reviewed source directly answers AgentTrace's exact A/B/C question with identical initial context, identical tool access for B/C, and exactly one feedback-assisted repair. That gap is the project's intended contribution; it is not evidence that the hypotheses are true.
